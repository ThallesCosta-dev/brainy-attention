    1 O problema

    Um modelo de linguagem precisa representar cada palavra levando em conta as outras palavras da frase. A palavra “bebeu” só faz sentido pleno perto de “gato” e “leite”.

    “o gato bebeu leite”

    Cada token recebe uma representação numérica chamada embedding — um vetor de números.

    Por que isso é necessário?

    Sem contexto, “banco” em “sentei no banco” e “fui ao banco” teriam o mesmo vetor. A atenção deixa cada token misturar informação dos outros.

    O que está acontecendo matematicamente?

    Transformamos uma matriz X de n tokens × d dimensões em outra matriz do mesmo formato, mas onde cada linha é uma média ponderada das linhas originais.

    2 Embeddings

    Cada linha de X é um token. Aqui usamos apenas 3 dimensões para conseguirmos ver os números; modelos reais usam centenas ou milhares.

    X — clique nos números e edite

    Por que isso é necessário?

    Computadores não operam sobre letras. O embedding transforma cada token em um ponto no espaço, onde “perto” significa “parecido”.

    O que está acontecendo matematicamente?

    X ∈ ℝn×d, com n = número de tokens e d = dimensão do modelo. Aqui d = 3, valor didático.

    3 Query, Key e Value

    Três projeções lineares da mesma matriz X. São só multiplicações de matrizes com pesos aprendidos.

    Q = X·WQ
    K = X·WK
    V = X·WV
    WQ (editável)
    ↓ X · WQ
    Q

    Query: “o que este token está procurando?”

    WK (editável)
    ↓ X · WK
    K

    Key: “que tipo de informação eu ofereço?”

    WV (editável)
    ↓ X · WV
    V

    Value: “qual conteúdo eu transmito?”

    Por que isso é necessário?

    Um mesmo token precisa de papéis diferentes: quem pergunta, quem se anuncia e quem entrega conteúdo. Três matrizes de pesos dão esses três papéis.

    O que está acontecendo matematicamente?

    Multiplicação de matrizes: o elemento Q[i][j] é o produto escalar da linha i de X com a coluna j de WQ. Nada de não-linearidade aqui — são projeções lineares.

    4 Produto QKᵀ

    Scores = Q·Kᵀ

    Cada célula mede a compatibilidade entre a Query de um token (linha) e a Key de outro (coluna).

    Heatmap dos scores brutos — passe o mouse ou clique nas células
    Passe o mouse sobre uma célula.

    Por que isso é necessário?

    Precisamos de um número que diga “quanto o token A deve olhar para o token B”. O produto escalar faz isso: vetores apontando na mesma direção dão valores altos.

    O que está acontecendo matematicamente?

    S[i][j] = Qi · Kj = Σc Q[i][c]·K[j][c]. O resultado é uma matriz quadrada n×n.

    5 Scaling

    Attention(Q,K,V) = softmax( Q·Kᵀ ⁄ √dk ) · V

    Dividimos os scores por √dk para evitar valores grandes demais, que deixariam o softmax quase binário e travariam o aprendizado.

    Q·Kᵀ (bruto)
    ÷ √dk →
    Q·Kᵀ / √dk

    Por que isso é necessário?

    Com dk grande, o produto escalar soma muitos termos e cresce. Scores enormes fazem o softmax devolver quase 1 e 0, e os gradientes somem.

    O que está acontecendo matematicamente?

    Se as entradas têm variância ~1, o produto escalar de dk termos tem variância ~dk. Dividir por √dk devolve variância ~1.

    6 Softmax

    softmax(xi) = exi ⁄ Σj exj

    O softmax transforma uma linha de scores em pesos positivos que somam 1.

    tokenxiexipesobarra

    Por que isso é necessário?

    Queremos uma média ponderada. Para isso os pesos precisam ser não-negativos e somar 1 — exatamente o que o softmax garante.

    O que está acontecendo matematicamente?

    A exponencial amplia diferenças e elimina negativos; a divisão pela soma normaliza. Somar uma constante a todos os x não muda o resultado.

    Cada linha responde: “para onde este token está olhando?” Clique numa linha para ver as conexões.

    Por que isso é necessário?

    É aqui que “contexto” vira número: a linha do token “bebeu” mostra quanta informação ele puxa de cada outro token.

    O que está acontecendo matematicamente?

    A = softmaxlinha(Q·Kᵀ/√dk), com cada linha somando 1.

    8 Weighted Sum

    Output = A · V

    A saída de cada token é a soma dos vetores V de todos os tokens, cada um multiplicado pelo seu peso.

    Representação contextualizada

    Por que isso é necessário?

    O vetor final já não é só “bebeu”: ele carrega pedaços de “gato” e “leite” na proporção dos pesos.

    O que está acontecendo matematicamente?

    Outi = Σj A[i][j]·Vj — uma combinação convexa das linhas de V.

    10 Atenção causal

    Em modelos que geram texto, um token não pode enxergar o futuro. Posições futuras recebem −∞ antes do softmax, o que zera o peso.

    Máscara (1 = permitido)
    Scores após máscara
    Pesos após softmax

    Scores → Máscara → Softmax → Attention

    Por que isso é necessário?

    Durante o treino o modelo vê a frase inteira. Sem máscara ele “colaria” a resposta olhando o próximo token.

    O que está acontecendo matematicamente?

    Somamos −∞ (na prática, um número muito negativo) onde j > i. Como e−∞ = 0, o peso vira 0.

    Precisão conceitual

    • Q, K e V são projeções lineares de X.
    • Q·Kᵀ produz os scores de compatibilidade.
    • √dk é o fator de scaling.
    • Softmax converte scores em pesos que somam 1.
    • Os pesos combinam as linhas de V.
    • Multi-Head executa várias projeções/atenções em paralelo.
    • Na atenção causal, posições futuras são mascaradas.
